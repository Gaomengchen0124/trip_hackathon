# 智能推荐模块范围与规则

版本：1.1。日期：2026-10-16。适用项目：Gaomengchen0124/trip_hackathon。

本文记录产品负责人已确认的功能范围，供开发助手、推荐模块、规划模块和数据库同学共同使用。实现与启动见[开发和配置说明](implementation.md)。规划交接仅沿用现有 lineId 跳转。

## 目标与职责

在现有“我的圣地巡礼”项目中，帮助用户根据内容兴趣发现作品及已有巡礼路线，再进入已有路线介绍与规划流程。设计支持持续扩充 IP，不将当前目录数量写死在界面、提示词或算法中。

- 推荐模块：首页“智能推荐”入口；旅行灵感推荐；首次登录后可跳过的内容兴趣选择；已有兴趣读取（个人中心编辑由对应同学负责）；路线推荐、解释与反馈；DeepSeek 服务端接入；选定路线后的信息交接。
- 规划模块：路线内活动偏好、景点预选、手动调整、必去点、排程、地图、时间与取舍。路线介绍页由对应页面负责人维护，推荐模块不自行修改其内容。
- 数据库模块：标签、用户画像、作品、路线、地点及关联关系、数据查询与持久化；具体表结构和服务接口待共同确认。
- 推荐卡片可展示资料中的代表景点，作为路线亮点，不代表已勾选、已排程或保证可游览。

## 旅行灵感推荐 discover

首页智能推荐卡片位于“选择你的圣地巡礼之行”标题与已有路线之间，悬浮效果与路线卡片一致。推荐页只保留旅行灵感入口，移除“我有喜欢的作品”模式；按指定作品找路线继续使用已有首页功能，避免重复入口。

起点是内容兴趣、目的地范围或一句话需求。可跨作品和城市推荐，说明“为什么你可能喜欢”。最多展示三条路线，控制重复 IP；不足三条不凑数。支持登录后收藏路线和本次反馈“暂不感兴趣”。收藏复用既有路线收藏接口，不改变本次筛选或长期画像；游客点击收藏时须先完成登录。

作品偏好与自由描述合并为一块可选的“偏好补充”：一个文本框可写作品、人物和故事兴趣，同一区域可点选已收录作品。点选作品仅用于排序，不限定只能推荐该作品。用户可填写任何喜欢的作品，包括未收录作品、作者／版本及喜欢的原因；AI 在推荐时分析其内容类型、题材与故事氛围，并映射到现有路线。未收录作品不自动成为新路线。所有偏好均可留空。

筛选摘要整条可点击展开／收起；点击面板外空白区域也会收起，输入保留且不自动重新推荐。保留吸顶与面板内滚动。通过“查看路线”进入介绍页顶部；从推荐进入的路线页增加“返回推荐筛选”，恢复条件和结果并展开筛选，不自动调用模型。浏览器返回则恢复之前位置。

## 用户画像与输入

登录成功后为未填写兴趣的用户提供四步卡片引导：内容类型、故事题材、故事氛围、喜欢的作品，每次一题，均可跳过，也支持整体跳过和返回上一题；中途登录后回到原页面并保留选择。游客可使用推荐。跳过后普通刷新不重复阻拦，下次主动登录可再次选择；已保存非空兴趣不重复询问。个人中心的兴趣编辑由对应同学负责，推荐页移除“编辑长期兴趣”入口。登录兴趣弹窗和推荐页带入按钮统一称为“我的兴趣”。

第四题同时提供自由填写和已收录作品快捷选择，均可选。自由填写内容保存为 favoriteWorks，原有 ipIds 继续用于已收录作品。推荐页带入时在“偏好补充”展示，可本次移除并补充描述，不改动已保存画像。

长期画像包含：内容载体（小说、影视剧、电影、动漫、文学散文等）、故事题材（科幻、悬疑、奇幻、历史、都市、青春等）、喜欢的作品或人物。枚举是候选方案，最终使用数据库统一字典和稳定标签 ID。作品版本须区分，不能把原著地点自动解释为改编作品取景地。

本次输入可包含：内容标签、作品／人物偏好、目的地范围、自由文本；日期、每天时长统一在规划页填写。用户可以只填写部分信息。优先级为用户本次明确选择高于长期画像，高于 AI 推测。本次反馈默认不改长期画像，用户主动选择保存后才更新。

Citywalk、购物、美食、咖啡、步行量、远郊接受度和必去点等由规划模块提供交互。用户在推荐自由文本中主动提到这些要求时，提示在规划页设置；推荐模块不另建相同表单，也不据此承诺已经完成排程。

## 推荐依据与数据约束

- 沿用 ipId、lineId、poiId，不自行重新编号。新概念字段如作品版本、地点实体 ID 须与数据库同学确认。
- 同一地点可关联多个作品；基础位置数据与作品关联说明分别维护，沿用现有 ID 的兼容关系。
- 缺失信息是未知，不等于支持或不支持。只有可靠数据支持时，才判断路线满足某项条件。
- 用户明确限定的目的地与排除条件应被尊重；冲突时解释并请用户选择，不自动放宽。
- 原著提及、影视取景、官方主题体验、主题延伸是不同关联，不互相冒充。
- 不编造作品、地点、引文、坐标、开放信息或实时票价。不以无校准的百分比冒充匹配准确率。
- 题材、氛围等软偏好可用于排序，但应解释未满足的偏好；不可把 AI 解析直接当作用户确认。

## DeepSeek 的职责

服务端提供当前有效候选摘要，由模型理解需求、排序并给出基于资料的理由。服务端校验输出结构、候选 ID、字段与硬条件，展示名称和图片来自项目数据。模型不决定实际行程时间和点位安排。

密钥由服务端环境变量提供，不使用 VITE_ 前缀，不进入浏览器、Git、日志或交接材料。接入时验证账号可用模型；模型名、超时和调用上限可配置。开发 skill 不会自动成为 DeepSeek API 的运行时上下文，后端须显式组织请求。

结果中的“AI 理解的偏好”明确标为推测，只用于本次排序，不自动写回长期画像。对于不熟悉或有歧义的作品，提示补充作者、版本或喜欢的原因，不强行为其赋标签。

模型失败时保留用户输入，可展示标为“基础推荐”的规则结果，不伪装成本次 AI 成功结果。本次推荐条件和结果保存在当前标签页，恢复期限为两小时，按账号隔离；不新增规划草稿。

## 验收重点

推荐页无重复作品模式；灵感推荐可跨作品发现；可选偏好合并；整条摘要展开和面板外收起均保留输入；查看路线到达顶部；不同输入会改变排序和解释；游客与跳过画像可用；已知与未知状态清楚；无候选有可操作反馈；选定路线能进入现有流程；用户输入来源明确且原行程不被意外覆盖；扩充有效数据后不需要修改硬编码目录。

推荐模块与规划模块的字段和现有资料见[对接文档](planning-handoff.md)，只需对方补充的事项见[简短提问](planning-questions.md)。

推荐来源标识（包括“基础推荐”）可点击打开说明弹窗；基础推荐说明提供“按当前条件重新推荐”，不会直接把基础结果切换成 AI 结果。首页“…”进入全部路线栏目时回到顶部，浏览器返回仍恢复原位置。
