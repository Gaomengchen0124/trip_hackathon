# 账号体系 · 第二轮

本轮只实现演示验证码表单和弹窗，不发送短信或邮件，不上传或持久化表单账号。所有输入账号最终进入第一轮同一个 demo-reader 用户，不能据此验证真实身份。

## 验收路径

从项目根目录用 HTTP 静态服务打开 demo.html。若第一轮已登录，先退出。

1. 点“体验登录（演示）”，打开登录弹窗。
2. 手机号仅支持中国大陆 +86 的 11 位号码；邮箱有基本格式校验。
3. 点“获取演示验证码”，页面明确显示 123456，进入 60 秒倒计时；没有实际发送。
4. 输入不足六位、错误验证码或不获取就直接登录，出现对应提示。
5. 获取后修改账号、切换登录方式，旧验证码无法验证新账号。重试倒计时在当前页面内共用，关闭重开弹窗也不会重置；刷新会重置，不能替代服务端限流。
6. 验证码五分钟有效，成功使用后失效；输入 123456 登录，弹窗关闭并显示演示用户。
7. 关闭按钮、Esc、点击遮罩可关闭弹窗；关闭后恢复页面滚动和原入口焦点。弹窗使用原生 dialog，支持键盘焦点约束。
8. 退出和刷新恢复沿用第一轮行为。

## 合并文件

在第一轮基础上，将以下文件按相对路径合入完整 Vue 工程：

- src/auth/login-form.mjs
- src/auth/login-dialog.mjs
- src/auth/login-dialog.css
- src/components/AuthStatus.vue（已改为打开弹窗）

wish-feature 包附有相同四个文件，以便其首页独立合并。两个包只需合并一份。不需要新增 npm 依赖。Vue 通过 AuthStatus 导入样式；原生 demo.html 通过 link 引入同一份样式。弹窗是共用 DOM 模块，Vue 入口在卸载时调用关闭函数清理实例、计时器、订阅和滚动状态。

changes.patch 和 manifest.json 仍描述此前组件交付，并不包含本轮内容，使用上面的文件清单合并。
