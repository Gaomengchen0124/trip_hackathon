# 字段规范（人 A · 步骤 1）

> 这份文件是给**所有填内容的人**看的。填之前先读一遍，能省掉大量返工。
> 现有三条线：`data/lines/fanhua-shanghai.json`（繁花·上海，**最终详细版**）、
> `data/lines/longzu-beijing.json`（龙族·北京）、`data/lines/longzu-japan.json`（龙族·日本）。
> 逐项填写用的表单见 `data/填写模板.md`。
> 本文件只定义「每一格该填什么」，点位内容以 JSON 为准。

---

## 〇、三条铁律

1. **引文必须逐字来自原著或改编作品，必须标出处。** 查不到就留空，**不许自己写、不许改写、不许"大意如此"**。
2. **书中查不到对应原文的地点，直接删掉，不要硬凑。** 宁可只有 6 个点，不要有 1 个假点。
3. **所有 `【】` 标记都是待填项**，填完必须全部消失，否则视为未完成。

> 所有点位都是「**地点 + 作品**」的绑定。没有原文支撑的地点，在这条线里没有意义。

## 二、IP 点位字段（type = `ip`）

每条线 8 个（凑不齐 6 个也行，路径见下）。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `poiId` | string | 北京 `bj-ip-01`~`08`；日本 `jp-ip-01`~`08` | 固定，不要改 |
| `lineId` | string | `longzu-beijing` / `longzu-japan` | 与 `line.lineId` 一致 |
| `type` | string | 固定 `ip` | |
| `name` | string | ≤12 字 | 用**现在的正式地名** |
| `alias` | string | ≤20 字 | 书里/剧里的叫法，没有就留空 |
| `lng` / `lat` | number | 保留 6 位小数 | 在地图上点一下取，不要凭感觉写 |
| `cluster` | string | 从上面 8 / 6 个里选 | |
| `tier` | string | `S` / `A` / `B` | **`S` 最多 3 个** |
| `durationNormal` | number | 30-180（分钟） | 正常游玩要多久 |
| `durationRush` | number | 约 `durationNormal` 的 50% | 打个卡就走要多久 |
| `intro` | string | **≤50 字** | 详情页显示的景点介绍 |
| `quotes` | array | **至少 1 条，最多 2 条** | 见下 |
| `realPhoto` | string | 固定路径 | `img/{poiId}.jpg` |
| `photoCredit` | string | | 图片来源 + 授权说明，**必填** |
| `skipNote` | string | ≤30 字 | 被建议舍弃时给用户看的理由 |
| `tips` | string | ≤30 字 | 打卡贴士（光线、时间、机位） |

### quotes 数组（重点）

**第一格永远填原著，第二格填影视/动画/漫画里的台词（如果有）。**

> 两格的 `kind` 只有两个合法值：`原著` 和 `台词`。**这是前后端契约，不要自创别的值。**

```
{
  "kind": "原著",
  "brief": "卡片上显示，≤20 字",
  "full": "详情页显示，80-120 字",
  "source": "《龙族》第 X 章"
}
```

```
{
  "kind": "台词",
  "brief": "“……”≤20 字",
  "full": "“……”\n“……”  80-120 字，多条对话换行",
  "source": "动画《龙族》第 X 集  /  漫画《龙族》第 X 话"
}
```

| 规则 | 说明 |
| --- | --- |
| `brief` 和 `full` **分开写，不是截断** | 20 字要能独立成立；100 字要能讲完整 |
| 台词那条必须写成**对话形式** | `“……”` `“……”`，不要写成叙述。影视版只放台词，**不放截图** |
| `source` 必须具体到**章 / 集 / 话** | 只写"《龙族》"不算合格 |
| 没有改编作品，或找不到台词 | 第二条整条删掉。**不要为了凑格式编对话** |
| 无论如何至少留 1 条 | 两条都找不到 → 这个地点删掉 |

> 卡片来源：S6 卡片显示景点图 + 原著 `brief`；S7 详情页显示 `full`。
> 影视线（如剧集/动画）在卡片上显示的是**台词对话**，不显示剧照。

## 四、命名与路径规范

```
数据里写：img/bj-ip-01.jpg
文件实际放在：public/img/bj-ip-01.jpg    ← 一律 jpg，长边 ≥1200px
封面同上：    img/fanhua-shanghai.jpg  →  public/img/fanhua-shanghai.jpg
数据：        data/lines/fanhua-shanghai.json
```

- 图片文件名**必须等于 poiId**，不要用中文名
- 一张图只能用在**一个**点位上

## 五、填完之后怎么自检

```bash
node data/validate.mjs --rules                          # 看规则表
node data/validate.mjs data/lines/longzu-beijing.json   # 校验单条线
node data/validate.mjs --all                            # 两条线都校验
```

校验器会检查：

- 有没有漏填或还留着 `【】`
- `lng` / `lat` 是否落在该城市的 `_bounds` 范围内
- `cluster` 是否在允许列表里
- `S` 级点位是否超过 3 个
- `durationRush` 是否约为 `durationNormal` 的一半
- 同一 cluster 是否超过 4 个点
- 每条 `quotes` 是否有 `source`
- `photoCredit` 是否填了
- `realPhoto` 指向的图片文件是否真的存在

**退出码 0 = 没有错误，可以提交。**

## 六、降级路径（时间不够时照这个砍）

| 情况 | 怎么办 |
| --- | --- |
| IP 点位凑不齐 8 个 | 做 6 个，**绝不造假点** |
| 城市景点凑不齐 15 个 | 12 个也可以，但**每个片区至少留 1 个** |
| 某条线（如日本）来不及 | 只做北京线，日本线在首页标注"敬请期待" |
| 图片来不及配齐 | 先用同色系占位图，`photoCredit` 写"占位图，待替换" |
